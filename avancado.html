CSS Avançado

Pré-requisito: CSS Intermediário. Aqui o assunto é montar — e manter — layouts completos em projetos reais.

1. CSS Grid completo

Enquanto Flexbox organiza uma direção por vez, Grid organiza linhas e colunas simultaneamente — o layout da página inteira em uma regra só.

.pagina {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "sidebar header"
    "sidebar conteudo"
    "sidebar rodape";
  min-height: 100vh;
  gap: 1.5rem;
}

.sidebar  { grid-area: sidebar; }
.header   { grid-area: header; }
.conteudo { grid-area: conteudo; }
.rodape   { grid-area: rodape; }

display: grid; grid-template-columns: repeat(3, 1fr);

Grid fluido, sem media query

.galeria {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 1rem;
}

auto-fit com minmax(200px, 1fr) é um dos truques mais úteis do CSS moderno: cada coluna tem no mínimo 200px, e o navegador decide sozinho quantas colunas cabem na largura disponível, sem escrever nenhuma @media.

2. Design responsivo

/* mobile-first: regra geral pensada para a tela pequena */
.cartoes {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

@media (min-width: 768px) {
  .cartoes { grid-template-columns: repeat(2, 1fr); }
}

@media (min-width: 1024px) {
  .cartoes { grid-template-columns: repeat(3, 1fr); }
}

Essa ordem — regra geral primeiro, depois min-width crescente — é mobile-first: desenhar para a tela pequena por padrão, e abrir mais espaço conforme a tela cresce. É mais fácil de manter do que o caminho contrário (desktop-first com max-width), porque a maioria dos projetos atende mais visitas em celular do que em desktop.

Container queries

.sidebar {
  container-type: inline-size;
}

@container (min-width: 300px) {
  .card { display: flex; }
}

Diferente de @media (que reage ao tamanho da tela), @container reage ao tamanho do elemento pai — o mesmo componente pode ter um layout diferente dependendo de estar numa sidebar estreita ou numa área larga, independente do tamanho da tela inteira.

3. Animações

@keyframes aparecer {
  from { opacity: 0; transform: translateY(12px); }
  to   { opacity: 1; transform: translateY(0); }
}

.toast {
  animation: aparecer 0.3s ease-out;
}

@keyframes pulsar {
  0%, 100% { transform: scale(1); }
  50%      { transform: scale(1.05); }
}

.notificacao {
  animation: pulsar 1.5s ease-in-out infinite;
}
Parte do shorthandExemplo
nome da animaçãoaparecer
duração0.3s
timing functionease-out
repetiçãoinfinite, ou um número de vezes

Diferença para transition: transição precisa de um gatilho (:hover, uma classe adicionada via JS); @keyframes roda sozinha, com controle fino de várias etapas intermediárias (os 0%, 50%, 100%).

4. Especificidade e cascata

Quando duas regras miram o mesmo elemento, o navegador decide por uma combinação de três fatores, nesta ordem de prioridade:

  1. Importância: uma regra com !important vence quase tudo (evite usar)
  2. Especificidade: id > classe > tag, somando pontos por seletor combinado
  3. Ordem no arquivo: em caso de empate, quem vem depois vence
#topo { color: red; }           /* especificidade: 1 id = mais alta */
.aviso { color: blue; }          /* especificidade: 1 classe */
p { color: green; }              /* especificidade: 1 tag = mais baixa */

/* mesmo com p vindo por último no arquivo, #topo ainda vence,
   porque id tem especificidade maior */

@layer: organizando a cascata de propósito

@layer reset, base, componentes, utilitarios;

@layer reset {
  * { margin: 0; padding: 0; }
}

@layer componentes {
  .botao { padding: 0.6em 1.2em; }
}

@layer (CSS moderno) deixa explícita a ordem de prioridade entre blocos inteiros de CSS, independente da especificidade de cada seletor dentro deles — uma camada declarada depois sempre vence uma anterior, o que torna grandes projetos mais previsíveis.

5. Metodologia BEM

<div class="cartao cartao--destaque">
  <h3 class="cartao__titulo">Título</h3>
  <p class="cartao__texto">Texto</p>
  <button class="cartao__botao cartao__botao--desabilitado">Comprar</button>
</div>
.cartao { }                      /* Block */
.cartao__titulo { }              /* Element: bloco__elemento */
.cartao--destaque { }            /* Modifier: bloco--modificador */
.cartao__botao--desabilitado { } /* Modifier de um elemento */

BEM (Block, Element, Modifier) organiza nomes de classe para que toda classe tenha a mesma especificidade (uma classe só) — isso elimina brigas de prioridade, porque a ordem no arquivo passa a ser o único fator de desempate, de forma previsível.

6. Modo escuro

:root {
  --bg: #ffffff;
  --texto: #14181F;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #14181F;
    --texto: #f0f0f0;
  }
}

body {
  background: var(--bg);
  color: var(--texto);
}

prefers-color-scheme lê a preferência de tema que o próprio usuário já configurou no sistema operacional — a maioria dos sites modernos nem precisa de um botão de alternância manual, o tema certo já aparece sozinho.

Alternância manual (combinada com JS)

<html data-tema="escuro">
[data-tema="escuro"] {
  --bg: #14181F;
  --texto: #f0f0f0;
}

Quando existe um botão de troca manual, o padrão é um atributo como data-tema no <html>, alternado por um pequeno script — o CSS só reage ao valor do atributo, sem precisar saber como ele foi alterado.

7. CSS moderno

/* :has() — selecionar um PAI baseado no filho, finalmente possível */
.card:has(img) { padding-top: 0; }
form:has(input:invalid) { border-color: red; }

/* aspect-ratio — proporção fixa sem hack de padding-top */
.video-wrapper { aspect-ratio: 16 / 9; }

/* propriedades lógicas — pensam em "início/fim" em vez de "esquerda/direita",
   funcionam automaticamente em idiomas da direita para a esquerda */
.card { margin-inline-start: 1rem; padding-block: 0.5rem; }
RecursoResolve
:has()estilizar um elemento com base no que tem dentro dele — antes só dava com JavaScript
aspect-ratiomanter proporção (como 16:9 de vídeo) sem truques de padding percentual
propriedades lógicaslayouts que funcionam em idiomas da direita para a esquerda (árabe, hebraico) sem CSS duplicado

8. Introdução a Sass

Sass é um pré-processador: você escreve .scss, uma ferramenta compila para .css normal antes de ir ao navegador — nada de Sass chega a rodar "ao vivo".

// variáveis (diferente de --var, viram valor fixo após compilar)
$cor-principal: #1572B6;
$espaco: 1rem;

// aninhamento — reflete a estrutura do HTML
.menu {
  display: flex;

  a {
    color: $cor-principal;

    &:hover {       // o & representa o próprio .menu a
      text-decoration: underline;
    }
  }
}

// mixin — um "bloco de CSS" reutilizável, com parâmetros
@mixin botao($cor) {
  padding: 0.6em 1.2em;
  background: $cor;
  border-radius: 6px;
}

.botao-primario { @include botao($cor-principal); }
.botao-perigo   { @include botao(#c0392b); }

Essa é exatamente a mecânica por trás da customização do Bootstrap (visto no material de Bootstrap Avançado) — sobrescrever variáveis Sass antes de importar a biblioteca inteira.

Projeto do nível: landing page completa

  • Layout de página inteira com CSS Grid (header, conteúdo, rodapé)
  • Uma seção de cards com auto-fit/minmax, sem nenhuma @media para as colunas
  • Pelo menos uma animação de entrada com @keyframes
  • Suporte a modo escuro via prefers-color-scheme
  • Classes nomeadas seguindo BEM
  • Testado em pelo menos três larguras de tela (celular, tablet, desktop) usando o modo responsivo do DevTools
Para onde ir depois

Com HTML e CSS avançados dominados, o próximo passo é JavaScript — é ele que transforma essas páginas estáticas em algo interativo: formulários que validam de verdade, dados vindos de um servidor, interfaces que mudam sem recarregar a página.
